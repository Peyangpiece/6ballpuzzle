HEXDROP 堆積球・おじゃま球 本家映像基準 連続崩落修正版

【2026-08-16 パフォーマンス修正】
目的:
- アプリ全体のラグ感と球のカクつきを軽減する。
- 特に多数の球が同時に崩れる瞬間のメインスレッド負荷を下げる。
- 物理結果、着地点、おじゃま仕様は変更しない。

主な原因:
1. 120Hz物理1回ごとにupdateVisuals()を無条件で16分割していた。
   2盤面では最大約3840回/秒の全盤面視覚走査になり、大量崩落時に負荷が急増していた。
2. pileFlow衝突スケジューラが候補時刻ごとに最大145サンプルを使い、同じ支持球の位置を多数回再計算していた。
3. 描画を120Hzに固定していたため、144Hz/165Hzディスプレイでは描画間隔が不均等になり、マイクロスタッターが発生し得た。
4. 背景の大型グラデーションを毎フレーム再生成していた。
5. 重いフレームの直後に最大24物理ステップを一気にcatch-upでき、負荷スパイラルが起き得た。

修正:
- scheduled pile/garbage flowは解析式の絶対時刻評価なので視覚substepを1回に変更。
- legacy collision-gated pathのみ4 substepsを維持。
- pileFlowPositionAt()へ時刻別メモ化を導入し、同一時刻の支持関係を再計算しない。
- pileFlowWaveSafe()で全球位置を時刻ごとに1回だけ計算して共有。
- 衝突サンプル数を固定144から12〜48の適応式へ変更。
- requestAnimationFrameごとに描画し、最大1物理tick分だけrenderLeadで表示位置を補間。
- pileFlow、通常落下、ハードドロップ、回転の見た目をrenderLead対応。
- 1フレームの物理catch-up上限を24から8へ変更し、余剰は最大1tickだけ保持。
- 静的な背景グラデーションをオフスクリーンCanvasへ1回だけ生成して再利用。
- 毎球毎substepで作っていた未使用_framePrevオブジェクト生成を削除。

期待される負荷削減:
- 大量崩落中のupdateVisuals全盤面走査: 16回/physics tick → 1回/physics tick（約93.75%削減）。
- legacy経路でも16回 → 4回（75%削減）。
- pileFlow scheduler timestamp: 最大145点 → 最大49点、短区間では13点程度。
- 支持球位置計算は同一timestamp内で共有されるため、依存球が多い崩落ほど再計算削減効果が大きい。

検証:
- HTML内classic JavaScript構文チェック: PASS
- 分割JS 11ファイル個別 node --check: PASS
- pileFlowの物理時間・最終論理セルは変更なし。
- PYRAMID: 6球形状×4セット、0.5秒間隔仕様を維持。
- HEXAGON: 6球形状×6セット、0.5秒間隔仕様を維持。
- STRAIGHT: 12+11=23球を1セット同時落下、上下対応色一致仕様を維持。

【既存の連続崩落仕様】
- 堆積球は剛性0。おじゃま球は盤面実体化後、通常堆積球と完全に同じ物理。
- CLEAR/garbage materialize時にsettleAll()で合法な最終経路を生成。
- motionSeqは因果順序情報のみで、pile/garbage描画バリアには使わない。
- 60°接触スライドは円弧を維持。
- movingSupportId/followSupportIdsをfallPathへ保存し、動く支持球との接触距離を維持。
- HEXAGON中央空洞は正常仕様として維持。
- 通常の落下3球の剛性ロジックは今回変更していない。
